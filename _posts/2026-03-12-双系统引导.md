#### 1. UEFI/GPT 启动与 BIOS/MBR 启动

- UEFI 程序和 BIOS 程序是一个水平，都是 BIOS 芯片里的程序
- UEFI 程序更高级
- 进 BIOS 实际进的是 UEFI 程序的图形界面
- UEFI 能识别硬盘 GPT 分区表，更高级，能管理更大的磁盘
- 总之都负责硬件自检，之后启动 bootloader

#### 2. 选择哪个 bootloader？

- UEFI 程序会读取自己的配置来选择
- 其实就是进入 BIOS 设置界面那里，选择启动介质

#### 2.5 UEFI 固件和 UEFI 设置

- UEFI 固件：烧录在 BIOS 芯片上的程序本身，提供 BIOS 界面和配置选项
- UEFI 设置：逻辑和固件分开，NVRam 里

#### 3. EFI 分区

- 存放 OS 对应的 bootloader
- EFI 分区和 OS 内核分区的位置没有很大关系，可以不挨着
- bootloader 的配置文件会告诉它，其他 OS 或者 bootloader 在哪

#### 4. grub

- grub 是一个引导程序系统，由一套工具和配置文件组成
> grub-mkconfig, grub-install, grub.cfg

1. grub-install：安装引导程序的 efi 文件
    - `--target=x86_64-efi`：指定架构
    - `--efi-directory=/boot/efi`：指定 bootloader 的安装位置
        - 引导程序要放在 EFI 分区里，所以这个目录必须是 EFI 分区
        - 该目录需要手动提前挂载，并且满足 EFI 分区，FAT32 格式
    - `--bootloader-id=jimiss0`：给这个 bootloader 起个名，在 BIOS 里设置启动顺序的时候就能看到这个名字
    - 复制 efi 文件
        - 在安装 grub 时，各类编译好的 efi 文件、模块也会一并下载下来
        - 这些 efi 镜像是通用镜像，显然 prefix 需要由 grub-install 嵌入
        - 执行 grub-install 时，会把定制后的 efi 复制到 EFI 分区里
        
2. grub-mkconfig：读取用户配置和脚本，生成 grub 配置文件
    - `-o /boot/grub/grub.cfg`：指定配置文件生成位置
        - `/boot/grub` 是一个根分区目录，不在 EFI 分区下

- 问题1：引导程序和配置文件不在一个分区，且启动时没有系统，引导程序怎么找到配置文件？
    - 在执行 grub-install 时，配置文件的路径 `/boot/grub` 会被转换为磁盘分区地址（hdx, gpty），该地址作为 prefix 嵌入 efi 程序中
    - 有相应的驱动模块来负责解析 prefix，挂载文件系统，找到 grub.cfg
    - 除了配置文件，模块的路径也是同理

- 问题2：为什么先 install 后 mkconfig，install 时就要嵌入 config 路径
    1. mkconfig 依赖 grub.efi
    2. grub.efi 知道在 /boot/grub 下，会有一个 grub.cfg 配置文件，就行

- 问题3：grub的模块都在EFI内吗？
    - 在 /boot/grub/x86_64-efi 目录下
- 问题4：EFI 下有什么？
    - 只有一个 efi 文件
