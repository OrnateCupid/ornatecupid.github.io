### 密码更新

1. 业务流程
    1. 查询原密码
    2. 验证是否相同，当前密码与原密码，原密码与新密码
    3. 更新密码

2. 问题
    - 属于经典读后写问题，可能出现：
        - 更新丢失，脏读，不可重复读，幻读
    - spring 的解决方式：条件更新（CAS，与乐观锁思想类似）
        - 数据库乐观锁：
        ```
            UPDATE table
            SET    col = newValue
            WHERE  id = ?
            AND  col = expectedOldValue;
        ```
        - 该方法通过 update 的原子性保证不出现并发写问题，但不会自动重试
        - 若需要自动重试，需要再加事务
        
3. 使用事务
    - 如多个写操作封装
    - 使用事务 @Transactional
    - 注：update 在 where 条件不满足时**不会抛异常**，需要判断 SQL 的返回值来检查是否更新成功，若失败，需要手动抛异常触发事务回滚
