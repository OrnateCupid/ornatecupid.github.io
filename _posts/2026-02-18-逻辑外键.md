### 逻辑外键

1. 使用物理外键
    1. 写操作会被强制加锁 `INSERT INTO order(user_id) VALUES (1001);`
    2. 高并发下 `user` 表将会成为热点锁表
    3. 分库分表后物理外键不可用
    4. 级联删除限制

2. 逻辑外键
    - 数据库中不会声明外键关系，约束关系存在于业务与代码中
    - 代价：数据库不再为一致性兜底，需要自行解决各种一致性问题
    - 使用场景：
        - 微服务
        - 分库分表
        - 高并发

| 维度       | 物理外键（DB外键约束）    | 逻辑外键        |
| -------- | --------------- | ----------- |
| 是否在数据库声明 | 是：`FOREIGN KEY` | 否           |
| 约束检查位置   | 数据库引擎           | 应用层 / 服务层   |
| 插入/删除校验  | DB 自动拒绝非法数据     | 代码校验        |
| 是否支持跨库   | 不支持           | 可以        |
| 是否影响并发   | 会加锁，影响写性能       | 无额外DB锁      |
| 是否可控     | 不可定制策略          | 可自定义校验策略    |
| 适用系统     | 单体、低并发、强一致      | 高并发、分布式、微服务 |
